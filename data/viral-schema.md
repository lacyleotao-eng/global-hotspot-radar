# 爆款参考库 · 数据规范 v1

用途：每天采集真实爆款内容（公众号文章/贴图、头条文章/微头条），拆解其字数、图文、结构、标题套路，作为自家成品稿是否达标的**参照系**。
本库只做公开信息采集与结构化，不下载原文图片、不代发、不进任何平台后台。

## 一、四种形态 form（必填，枚举）

| 值 | 含义 | 平台 |
|---|---|---|
| `gzh-article` | 公众号图文文章 | 微信公众号 |
| `gzh-poster` | 公众号贴图/图片消息（以图为主，正文 500 字+） | 微信公众号 |
| `tt-article` | 今日头条文章 | 今日头条 |
| `tt-micro` | 今日头条微头条（短讯，300 字左右） | 今日头条 |

## 二、爆款怎么定义（爆款指数 viralScore，满分 100）

五个维度加权，**每个维度的原始信号都必须写明来源，不可见就是不可见，禁止编造互动数字**：

| 维度 | 满分 | 打分依据 |
|---|---|---|
| 阅读/播放信号 | 30 | 页面或榜单可见：10w+ / 100w+ 播放=30；1w–10w=22；1w 以下=12；完全不可见=0 |
| 互动信号 | 25 | 点赞+评论+转发+在看综合：显著高=25；中等=16；偏低=8；不可见=0 |
| 榜单信号 | 20 | 多平台热榜前列=20；单平台榜单前列=14；上过榜=8；无=0 |
| 传播广度 | 15 | 多平台转载/被拆解引用=15；少量=8；单一来源=3 |
| 时效性 | 10 | 采集时 24h 内=10；7 天内=6；更早=2 |

分档 tier：`S`≥85（现象级）、`A` 70–84（爆款）、`B` 55–69（热门）、`C`<55（上升期）。
`breakdown` 数组逐项写 `{label, points, note}`，note 必须写清这一分是怎么来的（例：阅读信号 30 分来自"页面显示 10w+"）。

## 三、信号来源标注 signals.source（必填，枚举）

`页面可见` / `榜单数据` / `第三方拆解` / `不可见`。
- 公众号阅读数外部通常拿不到，只能来自榜单或第三方拆解文，**必须标注，不得冒充页面可见**。
- 混用多种来源时在 notes 里逐项说明哪个数字来自哪里。

## 四、形态拆解 anatomy（本库的核心价值，必填）

这是给自家样例当标尺的部分，要能被**逐条对照**：

- `wordCount`：正文估算字数（整数）。抓不到全文就写 null 并在 verification.notes 说明。
- `paragraphs`：自然段数（整数或估算）。
- `subheads`：小标题/分节数（整数）。
- `images`：配图张数（整数或估算）。
- `titlePattern`：标题套路，用短标签，如「数字+结果」「身份反差+悬念」「痛点+反问」「热点借势」「具体金额+情绪判断」。
- `hook`：开头前 3 句怎么钩人（一句话概括写法）。
- `structure`：结构拆解数组，一般 3–5 项，如 ["开头用真实场景切入", "中段列数据对比", "逐条反驳常见说法", "结尾给行动建议"]。
- `highlightSkills`：重点突出手法数组，如 ["加粗关键数字", "短句独立成行", "每节一个小标题"]。
- `lessons`：可借鉴点数组，2–4 条，写给"我们下次怎么写"，必须具体可执行。

## 五、完整字段

```
id            可选，缺省由 form+title 生成
title         爆款原文标题（原样保留）
form          四形态枚举之一
account       发布账号名
platform      "微信公众号" 或 "今日头条"
url           真实可直达原文，且域名必须与 form 对应（公众号 mp.weixin.qq.com / 头条 toutiao.com）；域名不符会被入库脚本拒绝
publishedAt   原发布时间 ISO8601，不可知写 null
collectedAt   采集时间 ISO8601，必填
category      领域：情感/职场/科技/财经/社会/民生/健康/娱乐/教育等
region        "国内"（本库当前只做国内平台）
summary       100–200 字内容概要，只写事实
signals       {views, likes, comments, shares, favorites, wow, source}  均可为"不可见"
ranking       {name, position, duration}  榜单名/排名或在榜情况/在榜时长，无则写 null
viralScore    {total, tier, breakdown:[{label,points,note}], method}
anatomy       {wordCount, paragraphs, subheads, images, titlePattern, hook, structure, highlightSkills, lessons}
verification  {status, method, notes}   status 用 已核实/部分核实/待核实/未核实
tags          字符串数组
```

## 六、铁律

0. **平台归属硬闸门（最高优先级）**：形态决定平台，平台决定原文域名——`gzh-article`/`gzh-poster` 的 `url` 必须是 `mp.weixin.qq.com` 微信原文直链；`tt-article`/`tt-micro` 必须是 `toutiao.com` 系直链。门户转载页、榜单页、拆解文章只能作为线索，**不得作为该平台的爆款条目入库**。拿不到对应平台原文就留空，绝不拿其他平台凑数。`scripts/ingest_viral.py` 会自动拒绝不合规条目，拒绝原因写入 `data/viral/meta.json` 的 `rejected` 字段。

1. **数字不编造**：任何阅读/互动数字必须有来源；拿不到一律"不可见"并在 notes 说明。
2. **榜单数字不是页面数字**：第三方榜单/拆解文的数字标注清楚，不冒充平台页面数据。
3. **原链优先**：优先真实文章直链；用榜单页替代时必须写明"榜单快照、未取得原文直链"。
4. **拆解要具体**：anatomy 的 lessons 必须能直接指导写作，禁止写"内容优质""值得学习"这类空话。
5. **去重**：同一 URL 或同一标题只留一条，由 ingest_viral.py 自动合并。
6. **合规**：不收录政治敏感、违法违规、侵犯版权内容；图片只记录数量，不下载不转存。
