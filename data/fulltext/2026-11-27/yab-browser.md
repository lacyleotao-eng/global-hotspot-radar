![App+1｜Yab：开源、AI 友好的双内核浏览器，给舍不得 Arc 的你](https://cdnfile.sspai.com/2026/11/25/article/4be42e9b-cbc6-9779-a31a-ab1f94d5ea94.jpeg?imageMogr2/auto-orient/thumbnail/!1374x/gravity/center/crop/1374x/format/webp/ignore-error/1)
我一直很喜欢精致美丽的产品，例如 iPhone Air 和 Mac mini。但喜欢归喜欢，有时候美丽的产品也会让人下不去手。只靠美观的皮囊吃饭，这事在工具属性的产品上是行不通的。
![](https://cdnfile.sspai.com/2026/11/20/5e9c6884bf2a0d0de14dbb9c51cfa19c.jpg?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
几年前上手 Arc 浏览器时，它也给过我类似的感觉。在 Chrome 和 Safari 已经把浏览器形态打磨得高度成熟的背景下，竟然还有团队愿意把它推倒重来——把顶部标签栏搬到侧边、用 Spaces 隔离不同工作流，再配上 Peek 预览、Split View 分屏以及各种细腻的交互动效，处处都给人一种「别人都这么做，但我偏不」的叛逆感，当时（甚至现在）也戳中了不少人。
但就像 Arc 创始人后来反思的那样，设计团队做了许多自认为绝妙的功能，但绝大多数用户根本用不上。新鲜感褪去后，Arc 留给人的好感并没有维持太久。倒不是这些设计不够好，而是它似乎过于执着于交互形态的创新，花大力气重构了人操作浏览器的方式，却唯独忽略了浏览器最本质的属性：它首先得是一个轻快、好用的工具。这些藏在深处的繁复细节，反倒一步步拖垮了它的性能表现。
在尝试转换到 Arc 差不多一个月的时间里，我的热情也随之慢慢耗尽，最后还是默默退回了 Safari。最近看到 The Browser Company 宣布 Arc 将于今年 12 月 22 日正式关停时，我心里并没有太多「失去老友」的伤感，更多的是替它感到惋惜。一款曾经被寄予厚望、试图重新定义浏览器的产品，最终竟连继续存在的机会都没有了。
![](https://cdnfile.sspai.com/2026/11/20/be13e59cb34b5a99c3bff1b2f254cd54.PNG?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
就在 Arc 准备谢幕的这段时间，编辑给我推荐了一圈名叫「又一个浏览器」的玩意： Yab[（Yet Another Browser）](https://yetanotherbrowser.com/) （好好好你们都喜欢这样取名是吧）。刚点开官网，我差点以为 Arc 借壳复活了：侧边栏、Spaces、Peek、Split View，甚至连熟悉的 Command Bar 都悉数在列。更直接的是开发者完全没打算掩饰对 Arc 的偏爱，直接在首页写下了一句 Slogan：
> Keep Arc. Add hands.
Yab 肯定不是 Arc 正式落幕前唯一一个想要接过 Arc 衣钵的产品，勾起我好奇心的也不只是它和 Arc 如同一个模子里印出来的 UI，而是后面那半句「Add hands」。
![](https://cdnfile.sspai.com/2026/11/20/8f6fd860396a13644cdfd7ad2eb504dd.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
## 分分寸寸尽是 Arc
当年第一代 iPad mini 发布时，Apple 给它的广告语是「分分寸寸尽是 iPad」。拿这句话来形容 Yab，我觉得再贴切不过。
如果你曾是 Arc 用户，上手 Yab 的学习成本几乎为零。标志性的侧边栏悉数保留，标签页可以按工作、生活等场景归入不同的 Spaces。高频网页可以显示成图标固定在顶部，临时页面则留在下方。Arc 里的文件夹、分屏、Peek 预览这些核心交互也一个不少，甚至，你还能一键导入 Arc 浏览器的 Spaces、标签页和浏览记录。
![](https://cdnfile.sspai.com/2026/11/20/59d68aef3759bbab8ad0d60a2ee95f3a.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)![](https://cdnfile.sspai.com/2026/11/20/47ea6b599f152c6a31d389bdfc95c327.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
这其中，我一直很喜欢的 Peek 用起来也和 Arc 如出一辙：按住 `Shift` 点击链接，新页面便会以临时悬浮窗的形式弹出，看完随手关掉就能回到原处。虽然操作步骤未必少了几步，但这种延续了 iOS「触感触控」思路的轻量交互，省去了频繁切换标签页的割裂感，非常对我这种「苹果全家桶」用户的胃口。
说起来，要是它能支持 Mac 触控板的「用力按压（Force Touch）」触发就更好了，毕竟我一直对三维触控（3D Touch）念念不忘，Safari 默认的取词翻译对我来说也用处不大。
说到这里，有时我也会觉得 Apple 在交互探索上多少带点「锤子科技」的宿命感：早早端出一些超前的设计，中途遗憾砍掉，结果到了 AI 时代又换个形态重新焕发生机。压力触控如此，当年的 Touch Bar 也是如此。
![](https://cdnfile.sspai.com/2026/11/20/2ade8a03bdfdbe3ba26d5d8d08b66ba1.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
熟悉的 Command Bar 在 Yab 里，进化得颇有聚焦搜索和 Raycast 的影子。按下 `Command + T` 呼出面板后，除了搜索网页、切换标签页，还能直接检索历史记录、执行快捷指令、做计算与单位换算，甚至翻找剪贴板里复制过的内容。
![](https://cdnfile.sspai.com/2026/11/20/718bea8d43342391f74f428113e1ac40.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
现在已经有综合性的搜索框了，那要是以后功能多到一个页面塞不下了怎么办？按照 Apple 的话来说，下一步给它加个 Dock 栏就行了。开个玩笑。但作为一个习惯在 Mac 上靠快捷键提升效率的人，Arc 当初吸引我的就不全是炫酷的 UI，高效的键盘使用体验也是我所看重的一点。
![](https://cdnfile.sspai.com/2026/11/20/addd9222382b26b7985a82c72bb1c8d0.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)~~iTunesOS~~
Yab 继承了这套操作逻辑，还把阅读模式、网页翻译、广告拦截等常见功能，以及 Arc 标志性的 Boosts 和 Chrome 扩展支持一并带了过来。
有意思的是，尽管 Yab 主要基于 WebKit 引擎，但它还额外内置了一套 Chromium 内核。遇到兼容性问题时，可以随时切换到 Chromium，甚至连 WebKit 标签页都能运行 Chrome 扩展，彻底践行了一把「成年人我全都要」的准则。当然，这并不意味着你就可以快速地从 Chrome 和 Arc 完整迁移以往的使用习惯和插件，更何况 Yab 目前也还是一款相当年轻的软件，光凭一套精致的界面和长长的功能清单，还不足以证明它就是 Chrome 或 Arc 的最佳替代品。我当初也是这么被 Arc 迷住的。
![](https://cdnfile.sspai.com/2026/11/20/5c527756c388b8db16d191ded671bf05.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
好在 Yab 确实展现出了自己的思考，没有全盘照抄 Arc 那套略显执拗的设计理念。不喜欢侧边栏？一个快捷键就能把标签页重新切回顶部；追求专注浏览？也可以一键隐藏侧边栏和工具栏。它甚至还藏了不少我很喜欢的细节，比如能让文件夹自动追踪特定的 GitHub Pull Request 或 Issue 动态，不必每次都手动打开网页查看。
![](https://cdnfile.sspai.com/2026/11/20/db2f90830fc6cb065d583c888f10cfc0.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
## 同一副皮囊，截然不同的灵魂
Yab 的开发者 Serafim Korablev 在官网提到，这款浏览器主要由他一个人配合大量 AI Agent 共同开发，并在今年 11 月正式开源。要知道，当初的 Arc 可是由一整个团队打磨出来的产品，而现在一名独立开发者借助 AI，竟然做出了外观与功能都颇具神韵的继任者，真是感叹时代变了。
不过随着 AI 越来越深入地介入工作与生活，一个尴尬的矛盾也随之浮现：AI 可以做很多事情，却没法从很多地方获得上下文。比如我明明已经在浏览器里登录了某个平台，数据就在眼前，可想让 AI 帮忙整理时却频频碰壁，甚至有些平台还对 AI 的访问设下重重限制。哪怕信息近在咫尺，AI 也无法直接读取，最后还是得靠我手动把资料复制下来再粘贴给它。
Yab 给出的解题思路是，既然 AI 很难绕过壁垒拿到网页里的数据，那干脆让它自己打开浏览器。在 Yab 中，你可以直接接入已有的 Claude 或 ChatGPT 方案，让 AI 像真人一样在浏览器里浏览网页、新建标签页，甚至点击按钮和填写表单，让 Agent 拥有独立的标签页去执行多步骤任务。你既可以在一旁观察它的每一步操作，也能在必要时随时接手。
![](https://cdnfile.sspai.com/2026/11/20/ce36500edfa610ca40b3126fc8e94e80.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
举个例子，过去我想对比几个网站上的产品参数，得自己挨个点开页面，把型号、规格和价格抄录出来，现在则可以直接把需求丢给 Yab，让 Agent 自己去检索汇总。对于需要登录态才能访问的后台页面，只要浏览器里已经建立好了会话，Yab 也允许 AI 在获得授权的情况下直接读取，省去了为每个平台单独折腾接口的麻烦。
![](https://cdnfile.sspai.com/2026/11/20/be633d2fa8c7243e2e47fb1e007dd2ee.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)![](https://cdnfile.sspai.com/2026/11/20/450e5946a8dbb1d2686083e0e67e943a.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
不过，比起内置的 Agent，Yab 还有一个更戳我的设计：MCP。如果你最近用过 Codex、Work Buddy 或 DeepSeek Harness 这类 Agent 工具，对这个词一定不陌生。你可以把 MCP（Model Context Protocol）理解成 AI 世界的「USB-C 接口」，只要软件在开发时为自己装上一个，AI 就能像插上一根「USB-C 数据线」一样直接接入，按照软件开放的规范读取数据并执行操作。
至于我为什么如此看重这一点，还得先吐槽一下如今的软件厂商们。AI 浪潮起来之后，几乎所有厂商都都不希望自己的数据流出，有急着往自家产品里塞一个 AI 助手。写作软件要加 AI，笔记软件要加 AI，连浏览器也恨不得把对话框摆在最显眼的位置。可问题是，我真的需要这么多各自为战的 AI 助手吗？既然 Codex 和 Claude Code 已经深度融入了我的日常工作流，难道为了实现网页自动化，我还得被迫去适应一款浏览器的专属 AI，甚至为此再买一份订阅？
Yab 对此的态度就很洒脱。它不仅允许调用现有的 AI 方案，还通过 MCP 和命令行工具，把浏览器的底层操作能力直接开放给外部 Agent。打开 Yab 的 `Settings → Developers`，找到 Codex，点击安装或配置 MCP 的选项。官方提供一键安装，会同时配置 Yab`-browser` MCP Server 和相应的 Skill。之后，我就可以在 Codex 里输入：
> 使用 $Yab-browser，通过 Yab 打开我已经登录的网站，读取当前页面的内容，帮我……。
![](https://cdnfile.sspai.com/2026/11/20/fefb3e6fe3f409dbbe53e69b969ddb47.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
这意味着 Yab 都不需要成为我的「主力浏览器」，只需要和其他 Agent 工具一样常驻后台，充当一名随叫随到的协作伙伴就行。相比那些依赖屏幕截图、盲猜坐标模拟点击的通用桌面 Agent，浏览器本身能够提供清晰的页面 DOM 结构和原生交互能力，执行起来还是省心太多。
当然，考虑到目前的 AI 还不具备独立承担风险的能力，一旦涉及消息发送、资金支付或数据删除等敏感动作，Yab 依然会停下来交由你手动确认。同时，你的私密标签页也对 Agent 完全不可见。
说起来，Arc 的原班人马如今也在打造一款名为 Dia 的 AI 浏览器。把 Dia 和 Yab 放在一起对比会发现，两款产品虽然都带着 Arc 的基因，但对 AI 的理解却走向了两个方向——Dia 更像是一套以浏览器为入口的「全能 AI 工作台」，试图打通网页与 Gmail、Slack、Notion、Google Workspace 等服务，帮用户总结邮件、沉淀资料、生成报告，希望主动理解你的工作流并接管一切。但这种高度整合的生态不仅带着浓厚的海外办公色彩，在国内很容易水土不服，而且对于那些本身就有开放接口的效率工具，让 AI 直接读取结构化数据，显然比在网页端绕一圈更高效、也更私密。
![](https://cdnfile.sspai.com/2026/11/20/ece43389b04076857a47c977c80e9bc4.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
相比之下，Yab 的定位克制得多。它不想成为统管一切的「工作中心」，而是甘愿退居二线，做一座「人与 AI 共用的数据桥梁」。就我个人而言，我也更偏爱 Yab。我始终认为，未来的软件不该个个都想当全能选手，每个人都有自己偏爱的 AI Agent 和模型、习惯的快捷键和和花了许多心思才调教顺手的工作流。
让数据都困在某个 App 或平台里，怎么看都像是一种 Web 2 时代的习惯遗留。
## 变革前夜
想到这里我才意识到，自己过去评价一款好软件的标准，或许也该跟着更新了。以前喜欢一款 App，往往是因为它的 UI 足够漂亮，或者某个功能刚好切中痛点，但最近折腾完各种 AI 工具后，我慢慢发现「有没有给 AI 留出入口」，正在成为我挑选软件时越来越在意的一件事。
这并不意味这 UI 设计变得不重要了，恰恰相反，我依然迷恋那些细腻的动效、恰到好处的交互，以及开发者藏在角落里的小巧思。只是过去我们总在研究「人应该怎样操作软件」，而现在，似乎也得开始琢磨「AI 应该怎样操作软件」了。
比如当我想让 AI 帮忙梳理待办事项时，最理想的状态是它能直接读取我授权的日历、聊天记录和邮件，而不是像人一样，靠着 Computer Use 在各个窗口之间来回截图、翻找。像 MCP 这样的协议，恰好让不同软件有机会以一种相对统一、优雅的方式向 AI 开放能力。
![](https://cdnfile.sspai.com/2026/11/20/bc5a547903265946b91ba8d5b933a796.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)最接近这个概念的其实是就是 Apple WWDC 2024 上介绍的 Apple 智能大饼。虽然至今仍未完全实现，但它的概念依旧十分超前。在大家对觉得 AI 是个聊天机器人的时候，Apple 已经意识到 AI 未来的方向应该是个人 Agent
只不过，现实中的互联网还远没有做好准备，许多平台依然把数据锁在围墙里，不少软件也压根没有提供适合 Agent 调用的接口。从这个角度看，Yab 这种让 AI 直接接管网页操作的方式，倒像是一种相当务实的折中方案。尽管网页改版、登录验证、Agent 偶尔犯迷糊等问题依然存在，但至少 Yab 在当下给出了一个不错的解决方案。
Yab 的出现可以说也有一定象征意义。当年 Arc 花了很大力气重新设计「人该如何使用浏览器」，而 Yab 在继承这份交互遗产的同时，又顺手为 AI 打开了另一扇门。并且这款软件本身也是借助 AI 打造出来的。
它现在当然还算不上完美，双内核的切换与 Agent 的稳定性都还有打磨空间，但在 Arc 即将落幕的今天，我们也终于借助它看见了未来 Arc 应该成为的样子。
