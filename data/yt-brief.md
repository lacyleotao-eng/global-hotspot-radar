# 视频拆解稿 · 生产规范（唯一真源）

> 适用：`data/yt-digest/` 下所有「YouTube 长视频 → 一步步攻略」的稿子。
> 站点入口：首页「视频拆解线 · 视频攻略」。**每天 10 篇**，10 个类型不重样。
>
> 产能约束：单次自动化 **90 分钟硬上限**，一轮稳定产出 **2 篇**（字幕→抽帧→写稿→压图→push）。
> 所以 10 篇拆成 **5 个出稿轮次**，各自只取「计划里下 2 条还没写的」，任一轮挂掉只丢那 2 篇，后一轮自动补。
> 每日排期见第六节。

---

## 一、选题：从哪类视频里挑

类型库（每天挑 10 类，同一天不重复；同一支视频 `videoId` 不得二次拆解，选题脚本已按 `index.json` 自动去重）：

| Key | 类型 | 典型看点 |
|---|---|---|
| food | 美食探店 / 做饭 | 人均、必点、排队时间、怎么点最划算 |
| travel | 城市攻略 / 旅行 | 路线、交通、门票、几点去、住哪 |
| money | 赚钱 / 副业 / 生意 | 启动成本、获客、单价、真实流水 |
| invest | 理财 / 投资常识 | 规则、费用、风险点（不做个股建议） |
| work | 职场 / 效率 / 管理 | 具体动作、话术、工具组合 |
| tech | AI / 科技工具 | 能干什么、怎么配、坑在哪 |
| gadget | 数码测评 / 选购 | 参数取舍、价格区间、适用人群 |
| life | 人生感悟 / 情感 / 关系 | 只取可操作的部分，不写鸡汤 |
| health | 健康 / 健身 / 减脂 | 动作、频率、饮食、常见错误 |
| home | 家居改造 / 收纳 / 装修 | 预算、尺寸、施工顺序 |
| parenting | 亲子 / 教育 | 年龄分段做法，不贩卖焦虑 |
| study | 语言 / 考试 / 学习方法 | 每日安排、材料、避坑 |
| diy | 手工 / 维修 / 改造 | 工具清单、步骤、安全 |
| car | 汽车 / 用车 | 选购、保养、路况 |
| outdoor | 户外 / 露营 / 钓鱼 | 装备、点位、季节 |
| pet | 宠物 | 喂养、训练、就医 |
| fashion | 穿搭 / 美妆 | 场合、预算、单品 |
| create | 摄影 / 剪辑 / 创作 | 参数、流程、软件 |
| film | 影视 / 纪录片解读 | 只做信息型拆解，不搬运剧情 |
| law | 法律 / 办事 / 避坑常识 | 流程、材料、时限（不做个案建议） |

选片硬条件（缺一不选）：

1. 时长 **6–40 分钟**（太短没信息，太长一篇写不完）；
2. 有字幕：人工字幕优先，自动字幕可用；**完全没有字幕的不做**；
3. 信息密度够：片子里有具体价格、地址、时长、参数、步骤、材料之一，且能数出至少 5 个可执行动作；
4. 热度门槛：播放 ≥ 1 万，或发布 ≤ 14 天且明显在涨；老片只要能查到高播放也可；
5. 合规：不碰政治敏感、医疗诊断、个股荐股、违法操作；探店类不写"最正宗"这类绝对化结论。

## 二、事实纪律（比文采重要）

- **只写字幕里出现过的事实**。字幕没说的，一律写「视频里没说」，不补、不猜、不用常识填空。
- 每个关键数字/结论后面挂 `<span class="ts">00:12:13</span>`，时间戳必须能在原片对上。
- 口头夸张（"三千块""全广州最好"）不当作事实依据；要么不写，要么在文末「未采信」里点名。
- 有争议的说法单开一节，写清楚"视频里怎么说 / 可查的是什么 / 本文不下结论"。
- 平台/商家信息（地址、电话、营业时间）只写视频画面或字幕里出现的；没有就不写。

## 三、结构（照这个骨架写，步数 7–10）

```
<h1>标题：把最有用的那个数字/结论放进标题</h1>
导语：谁、花了多久、走完/做完什么，读者能得到什么（2–3 句）
<header> 素材：频道 · 时长 · 发布日 · 播放

0 先看结论：值不值得做 / 去         ← 3–4 个 KPI 卡片 + 适合谁 / 不适合谁
1 怎么开始：交通 / 准备 / 材料       ← 步骤化，能照着做
2 关键决策点：几点到 / 买哪个 / 怎么配 ← 表格对比
3..N 每一步怎么做                    ← 一节能写完的不要拆两节
N-2 避坑清单                         ← 表格：坑 / 怎么避
N-1 有争议的说法（有才写）
N  一页速查                          ← 无序列表，打印出来能带走
footer 事实来源 + 未采信 + 配图说明
```

写作口径：

- 第二人称 + 祈使句（"8:20 到门口"），不写"我们可以看到"。
- 一段不超过 4 行；能用表格就不写长段落。
- 标题 18–28 字，含一个具体数字；不用"震惊""必看"。
- 每节开头一句结论，再展开理由。

## 四、配图铁律（用户明确定过，违反即返工）

**允许的来源，只有两种：**

1. **原片截帧**（首选）：从播放器里取 1920×1080 原生帧，压缩成 1000–1200px 宽的 jpg。
2. **AI 生成示意图**：豆包 / ChatGPT 生成，图注必须写「AI 生成示意图（非现场）」。

**绝对禁止（一切"博主视角"素材）：**

- 博主本人出镜、正脸、半身、合影；
- 自拍视角、手持相机/手机的第一人称画面；
- 画面里有博主的手、手指、筷子夹持动作、举着菜单/物品的手；
- 路人/儿童的正脸特写（背影、远景人群可以）；
- 带频道水印、字幕条、播放器 UI 的画面（截帧前先确认没压字幕）。

**可以用的客观镜头：** 菜品、物件、工具、招牌、门面、街景、建筑、风景、信息牌、价目表、历史照片、地图。

数量与位置：

- 8–12 张；平均每 400–600 字一张，不要堆在开头；
- 首图放"这是哪儿/这是什么"，进正文前就让人有画面；
- 每张都必须有 `<figcaption>`：**画面说明 + `<span class="ts">视频截帧 00:12:13</span>`**；
- 封面用第一张（`meta.json.cover`）。

处理与体积：

- 宽度 1000–1200px，jpg q82–86，单张 < 250KB，整篇 < 2.5MB；
- 需要裁掉手/杂物时用 crop，不要用马赛克或模糊（会显得心虚）；
- 视频截帧不额外加滤镜、不加文字贴纸。

判定口诀：**这张图能不能换成别人在旁边拍的？能，就可以用；只有博主本人能拍到，就别用。**

## 七、已知坑（2026-11 实测）

- `yt-dlp` 直接下载视频会报 `Requested format is not available`（只剩 storyboard）：YouTube 对无 PO token 的客户端关掉了视频流。**改用 `scripts/yt_grab_frames.js` 在浏览器播放器里抽帧。**
- cookie 会被轮换，报 `Sign in to confirm you're not a bot` 就重跑 `scripts/yt_export_cookies.js`；需要 ego 里 YouTube 处于登录态。
- 纯暂停状态下 `currentTime` 赋值经常不落帧（静默停在 0 秒），抽帧脚本里必须"赋值 → 短播放 → 等帧"。
- 粤语等人工资讯轨在 `subtitles` 而不是 `automatic_captions`，`yt_transcript.py` 已经两种都试。

## 八、每天 10 篇怎么跑（排期与脚本）

一天 10 篇不是「跑一个大任务」，而是**排期 + 五轮出稿**。所有轮次共用一份选题计划，谁也不许自己乱选题。

| 时间 | 环节 | 干什么 |
|---|---|---|
| 09:40 | 选题计划 | `yt_discover.py --plan` → `inbox/<日期>-plan.json`，10 条、10 类、已去重 |
| 10:20 | 出稿 1 | 取计划里下 2 条 → 字幕/抽帧/写稿/压图 → push |
| 11:35 | 出稿 2 | 同上 |
| 12:50 | 出稿 3 | 同上 |
| 14:05 | 出稿 4 | 同上 |
| 15:20 | 出稿 5 | 同上，补齐到 10 篇 |
| 18:40 | 质检上线 | `yt_check_digest.py` 全量查 + 补缺口 + push + 线上复核 |

三个配套脚本：

```bash
python3 scripts/yt_plan_next.py --n 2      # 取计划里下 2 条（已写的自动跳过）
python3 scripts/yt_plan_next.py --stats    # 今天写了几篇、还剩哪些
python3 scripts/yt_check_digest.py         # 机械质检：图数/图注/时间戳/封面/步数/缺口
```

`yt_check_digest.py` 判不了的只有一件事：**画面里有没有博主出镜、自拍、手持、手/筷子、路人正脸**——这条必须每张图人眼过，判错即返工。

轮次设计的三条理由：

1. **90 分钟硬上限**：一轮 2 篇约用 60–75 分钟，留 15 分钟余量；一轮 3 篇在配图环节必然超时。
2. **落盘即 push**：每轮结束就 `yt_build_index.py` + `git push`，线上数字是分钟级往上爬的，不是等晚上一次性刷出来。
3. **缺口自愈**：每轮读的是「计划里还没写的前 2 条」，前一轮挂了，后一轮自然接手；最后一轮和质检轮负责把缺口补到 10。

## 九、遇到死路怎么处理（实测 5/10 会死）

11-27 实跑一轮，10 条计划里 **5 条写不出来**，原因只有三类：

| 死法 | 表现 | 处理 |
|---|---|---|
| 无字幕 | `yt_transcript.py` 报 `segments=0`，`yt-dlp --list-subs` 显示 has no subtitles | 立即弃，别硬啃画面 |
| 全片人物出镜 | 抽帧全是博主/教练/厨师本人，客观镜头 < 8 张 | 弃，不做「人物占比过高」的稿 |
| 单一机位口播 | 全片一张脸讲到底，只有文字卡 | 弃，凑不出图就是凑不出 |

弃掉时**必须留痕**，否则下一轮还会再撞一次：

```bash
python3 scripts/yt_plan_next.py --abandon <slug> --reason "无字幕轨"
python3 scripts/yt_plan_next.py --n 2      # 取下一批（已弃的自动跳过）
```

已弃的 videoId 会被选题脚本永久排除（`used_video_ids()` 读当天计划里的 `abandoned`）。

**所以计划要多排备胎**：`yt_discover.py --plan` 产出 **目标 10 + 备胎 5 = 15 条**，其中 `buffer: 1` 的是备胎。正选死光了就用备胎，不用重新搜。

**选题侧已经提前挡掉两类**：
1. 字幕探测：每条候选跑一次 `yt-dlp --list-subs`（约 5 秒），没字幕的直接不进计划——这一条就能挡掉实测 2/5 的死亡。
2. 人物风险排序：`health / fashion / pet / parenting / life` 这五类基本是「人对着镜头讲」，排计划时放最后，缺口优先落在它们身上。

## 十、storyboard 探针（选题阶段就挡掉「全片一张脸」）

写稿轮次最贵的浪费是「抽完帧才发现整片都是主持人」。YouTube 虽然关了视频流，但**还给 storyboard**：`sb0` 是 20 张 960×540 的均匀抽帧（一个 mhtml 约 700KB，10 秒下完）。

```bash
python3 scripts/yt_storyboard.py --plan --limit 15    # 给计划里 pending 的条目各出一张联络表
```
产出 `data/yt-digest/inbox/probe/<slug>.jpg`，用图片查看工具看：

- 人物/脸占比 **> 50%**，或几乎全是文字卡/界面 → 直接 `--abandon <slug> --reason "storyboard 探针：人物占比过高"`
- 有街景、店面、菜品、工具、房间、产品、风景等客观镜头 → 留着写

**实测对照**（11-27）：
- `$200k side hustle`：20 帧里 17 帧同一主持人 → 写不出 8 张客观图（已弃）
- `student guide to personal finance`：15 帧里 13 帧同一主持人 → 已弃
- `東京近郊一日來回`：车站、列车、街道、食物、店铺占一半以上 → 可写

这一条能把「死在配图不足」的比例从约 1/3 压到很低，代价是选题任务多花 2–3 分钟。
